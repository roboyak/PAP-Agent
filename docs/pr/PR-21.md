# PR21: maintain calibration escalation thresholds

Lesson: Re-evaluate recent errors with versioned thresholds, while keeping hard limits authoritative.

Checkpoint 6.1 feedback asked for threshold maintenance as operating conditions change.
PAP now checks recent point-power errors, compares two complete adjacent windows for an
error-drift signal, and shows review status in Inspector → Memory. Operators can preview
candidate ENV thresholds with a read-only CLI, review evidence, then restart with new settings.

## Architecture and behavior

Assessment uses the versioned policy instead of a hard-coded lifetime-average cutoff.
Publication preserves that assessment's feedback through checkpoint resume; no-outcome
assessments preserve `null`. Model routing/confidence may change, but power calculations,
voltage floors and T3/T5/T6/T7 authority remain unchanged. LangGraph state, bounded search,
agent contracts/tools, provider selection and optional LangSmith remain unchanged.

No migration: raw outcomes/metrics stay canonical; calibration JSON summaries gain policy,
windows, outcome IDs and review metadata. Read-only MCP and pgvector contracts are unchanged.
Old live outcomes expire from escalation statistics, not from the separate RAG retrieval policy.
Source, wing and forecast-version histories remain isolated; historical replay cannot use
later live feedback. Persistence risk is low; existing records are preserved.

CLI output shows a different candidate policy ID without changing saved outcomes or the

maintenance → Check current calibration. Expect sample counts, thresholds, review status,

replay disables the live calibration check and outcome evaluation. No hardware commands occur.

## Limits, docs and rollback

Defaults (0.25 kW, 20 samples, seven days) are demonstration settings. The review date is
configured metadata, not proof of human review. Error-mean drift is a proxy; this MVP has no
numeric confidence probabilities for ECE. Automatic tuning, per-wing thresholds and scheduled
notifications are deferred. Newer evidence and a reviewed tolerance are required for useful
retuning; changing the date alone cannot clear an error alarm.

README, howto, architecture, observability, capstone notes and
[maintenance procedure](../CALIBRATION_MAINTENANCE.md) describe the change. Submission artifacts
retain their original evaluation snapshots. Roll back code/config while retaining outcome,
assessment and publication history. No database downgrade or data deletion is needed.
