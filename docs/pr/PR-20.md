# PR20: start, pause and resume a historical simulator

Lesson: Compose durable single runs into a visible, resumable simulation.

Choose one wing, a starting time and 15/60-minute increments, then Start simulation.
PAP advances automatically to September 6 midnight Pacific (excluded), showing its clock,
progress and latest forecast. Pause finishes the current step; Resume continues it.
Results links every step to its fixed Inspector record while the runner continues.
The controls, output and assumptions fit at 1366×768; Run once and latest-source use remain.

## Architecture and persistence

One background task in the foreground FastAPI process calls the existing LangGraph workflow
sequentially. Step UUIDs are deterministic; interrupted work resumes the same checkpoint and
canonical publication. LangGraph state/nodes/edges and LangChain contracts/tools/budgets are
unchanged. Replay retains the wing/clock and generic-only memory; no live outcome writes.
Python retains validation, arithmetic and publication authority. MCP remains read-only;
pgvector, provider ENV switches and optional non-fatal LangSmith export are unchanged.

Migration `0010_simulations` adds one table for parameters, status and completed-step count.
Result summaries read canonical publications instead of copying forecasts into progress.
No existing tables, embeddings or checkpoints are rewritten. Fresh/previous-revision upgrades
and repeat migration preserve existing episodes. Migration risk: low.
Restart, or recovery after a database outage, leaves interrupted progress resumable.
The API also accepts an earlier `ends_at` for a bounded short replay.

Open http://127.0.0.1:8000. Choose MySolArk, DW 1.21, the recorded week, and noon August 30

Expect the count/clock/output to advance together. Changing pages must not stop the run.

No control commands or live outcome feedback are sent.

With the app running and any simulator paused, another terminal can make a three-step replay:

```bash
curl -sS http://127.0.0.1:8000/api/v1/simulations \
  -H 'Content-Type: application/json' \
  -d '{"wing":"1.21","starts_at":"2026-08-30T12:00:00-07:00","ends_at":"2026-08-30T12:45:00-07:00","step_minutes":15}'
```

Open `http://127.0.0.1:8000/?simulation=RETURNED_ID`; expect Finished after three steps.
To regenerate the silent MP4/WebM walkthrough and screenshots (FFmpeg installed):

```bash
uv run python scripts/record_simulator_demo.py --wing 1.21 --step 60
```

## Limits and rollback

One background simulation per foreground process; no multi-worker queue. Step time includes
PAP execution plus a one-second visual pause. Model calls follow existing ENV settings and
per-episode limits. The default optional interpretation agent remains off.
This replays recorded telemetry, with synthetic weather and retrospective voltage floors;
it is not battery physics or an unbiased accuracy benchmark. Counts are valid/withheld steps;
overlapping twelve-hour forecasts are never summed into weekly energy.

Rollback runtime/UI changes while retaining migration0010 and saved progress/PAP/checkpoint
history. Do not drop the new table to disable the UI. README, howto, architecture, runbook,
observability and capstone notes describe the simulator; older submission artifacts retain
their original evaluation snapshots. The repository remains private under the owner's control.
