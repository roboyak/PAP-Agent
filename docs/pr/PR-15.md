# PR15: readable run inspection and reusable app recordings

Lesson: Keep every debug panel tied to one run, and put the human explanation before raw records.

Adds a selected-run link and summary, restores its saved inspection records on reload, separates
source/calculation previews from completed runs, and preserves run memory during manual searches.
Tools, memory, model calls and workflow steps have readable summaries with expandable JSON.
Long actions show elapsed time and pending HTTP requests while conflicting controls are disabled.
No backend graph, model, numerical, database or MCP behavior changes.

`scripts/record_demo.py` records 2:30 and 9:00 silent walkthroughs using actual browser footage.
Editable chapter captions and narration guides explain each feature. Both videos inspect one
saved real Ollama run on the labeled sunny fixture and perform separate manual searches and
numerical previews. Browser contexts do not make new agent-generation calls, evaluate outcomes
or index memory; manual searches use the local embedding model. Health checks the current service.
FFmpeg exports MP4 and verifies duration and the absence of an audio track. Add narration and
host the video before submitting it as the required recorded presentation.

`make verify` passed: 44 unit/integration tests and 13 Chromium Playwright checks.
Browser checks include selected-run reload, manual-search separation, pending-action locks,
failed inspection with visible unavailability, and reload recovery. `node --check` and
`git diff --check` passed. Actual saved-run views were inspected at desktop and mobile widths.
Independent code, workflow/test, safety, architecture and documentation review found no
remaining blocker or major issue. Final MP4s are packaged in the following artifact refresh.
The real saved recording example is `18b31d85-5307-49d3-969d-3f45f1c5bf77`: valid,
selective reasoning, four Ollama model calls. This is a demonstration, not an accuracy rate.
