# PR25: stored Open-Meteo weather

Lesson: Preserve source identity and withhold incomplete evidence before forecasting.

New MySolArk runs replace the fixed weather ramp with stored weather for the selected
wing. Replay reads historical observations; live prefers complete hourly forecasts.
Context, Tools, model inputs, forecast explanations and published provenance identify
the source actually used. Sunny remains synthetic. Saved episodes recorded before this
change still show synthetic weather; they are not recalculated or relabeled.

## Architecture and boundaries

Weather/Solar MCP now accepts scenario, wing and replay time with the horizon start.
Its version-1 SourceResult envelope and 0..1 WeatherForecastInterval contract remain;
normalized row timestamps, update times and model versions are additive result metadata.
The same source DSN/site lookup as telemetry uses a read-only connection, 3-second connect
timeout and 3-second statement timeout. Queries select normalized columns only; no HTTP
calls, source writes, credentials, device identifiers, or raw source JSON enter PAP results.

Replay chooses the nearest Open-Meteo observation at/before **each interval start**, within
**90 minutes inclusive**. This uses actual weather across the twelve-hour horizon, so it
is retrospective simulation rather than a forecast known at the replay clock. Live uses
all twelve containing UTC-hour forecast buckets, with nonnegative CF <=1, a model version,
and update time at/before the telemetry anchor within **24 hours inclusive**. Local rows
are generated by SolarCast; its model version is retained rather than implying PAP made a
new Open-Meteo request. The first interval starts at the actual telemetry timestamp, with
no hour interpolation. Rails naive timestamps are interpreted as UTC; UI times stay Pacific.

Decision: retain the **0..1 bound**. For observations,
`factor = min(1, interval_irradiance / reference_irradiance)`; live forecasts use the same
ratio with capacity factor. Reference is the first selected input. A zero reference yields
zero throughout. Cloud effects already influence irradiance and are not applied twice.
This deliberately cannot amplify morning ramps or forecast sunrise from a zero PV reading.
The measured solar power is still multiplied by the factor. ReservePolicy.max_extra_power_kw,
when configured, and T5/T6 remain authoritative; no battery energy is allocated.

If any forecast hour is missing, invalid or stale, the whole horizon falls back to stored
observations. Live cannot use observations later than the telemetry anchor. A recent
observation alone cannot satisfy twelve future hourly starts within 90 minutes, so that
fallback returns **unavailable** and T3 withholds. A failed interval invalidates
the entire result. No mixed-source intervals and no implicit synthetic fallback.

LangGraph node structure, edges, state and checkpoints are unchanged. Existing LangChain roles,
model settings, tool scopes and budgets are unchanged; their context names the saved
weather source. LangSmith remains optional. Database migration risk: **LOW (no migration)**.
Weather content gets a digest in the new scenario key, so a revised forecast at the same
telemetry timestamp cannot collide with old weather rows. Existing episodes, evidence,
scenarios and outcomes remain append-only. PostgreSQL/pgvector and checkpoint schemas do
not change. New calculations use `solar-persistence-stored-weather-v1`; existing version
filters exclude old synthetic-weather outcomes from calibration and retrieved outcome memory.
Current live calibration in the API/CLI follows the new version; saved-run feedback stays
fixed. Sunny keeps `solar-persistence-demo-v1`. No orchestration or equipment-command paths
are added.

T8 independently validates the telemetry result from the existing recorded MCP acquisition.
Missing future weather can withhold a new forecast without blocking a fresh measured
outcome against an existing forecast. The shared telemetry checks still enforce timestamp,
age, wing and source; the existing newer-scrape and same-publication checks remain.

## Limits and rollback

This remains conservative solar persistence with constant measured load, zero battery
discharge and unconfigured live equipment caps. CF is the stored forecast model's shape,
not measured irradiance. Forecast freshness uses the hourly row's update time, not an
archived issuance time. Observations record the capture service's time. Model/provider
accuracy is not established. Real data gaps may increase withholding compared with the
earlier fixture-based playback. Old report/deck/video snapshots are retained as history.

Revert this commit to restore synthetic weather on new MySolArk runs. No database migration,
rollback SQL or source edits are needed; existing runs keep their saved provenance.
