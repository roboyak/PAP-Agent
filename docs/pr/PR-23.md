# PR23: timed narration and assembly for separately recorded clips

Lesson: Budget narration and demo actions together before recording.

The existing slide-only narration filled the presentation time limit. This script covers
all ten slides plus PAP and Inspector in twelve clips targeting **9:10 total**. Each clip
has words to read, screen cues, a filename and a duration. A small builder regenerates the
reading copy from JSON. The assembler joins narrated MOV/MP4 clips into one 1080p MP4.

The PAP demo first shows a one-day real telemetry replay, then explicitly opens a separate
saved model-assisted forecast. Inspector follows that same saved forecast. Its API records
confirm 0.622 kW first-hour power, 2.222 kWh over twelve hours, low confidence and five
actual local model calls. Slide 9's narration distinguishes its earlier 44/13 test snapshot
from PR22's 55/21 tests and 840 completed real replay steps. The deck itself is unchanged.

## Architecture and boundaries

Only local submission materials and media scripts change. No runtime, database, MCP,
LangGraph, agent contract, provider or observability changes. The assembler reads local
clips, keeps originals unchanged, normalizes dimensions/frame rate/audio format and joins
synchronized audio/video pairs. Trims default to zero and only change through the plan.
Each run creates a new output directory. It neither records the microphone nor uploads media.

## Optional human review

From the repository root:

```bash
uv run python submission/build_narration.py
make verify
mkdir -p output/narration-clips
```

Read `submission/artifacts/DragonWings_9_Minute_Recording_Script.md`. Expect ten slides,
two demos, filenames 01 through 12 and a 9:10 schedule. Record numbered MOV/MP4 clips with
the same screen dimensions and microphone, and save them in `output/narration-clips/`.
When all twelve exist:

```bash
uv run python scripts/assemble_presentation.py --clips output/narration-clips
```

Expect a new `output/recordings/presentation_*` folder containing MP4 and `assembly.json`.
Missing/duplicate clips, missing audio, invalid trims or FFmpeg failures stop assembly.
An out-of-range duration is reported for correction. Listen to the entire result and check
text legibility, audio clarity and cuts. Decode success is not proof of a good presentation.
