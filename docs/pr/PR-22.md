# PR22: show recorded solar, usage and surplus across selected days

Lesson: Keep recorded power, future estimates and playback time distinct.

The previous forecast chart looked like solar began at noon: it showed estimated surplus
from the chosen start time. Recorded day now shows actual solar coming in, site usage and
nonnegative solar left over, with plain explanations for night, morning and surplus.
Future estimate remains separate and explicitly does not model sunrise or sunset.

## Behavior and boundaries

Start day and End day default to August 30–September 5. The end day is included; matching
dates replay one day. The existing 15/60-minute controls still advance the clock. Fast/Normal/Slow changes the
0/1/3-second pause between steps, including while running; every PAP step still executes.
Chart day reviews a completed day with matching cards, source and Inspector episode;
Follow playback returns to the advancing day. Display clocks use Pacific time with minutes.
The six Inspector tabs remain intact, and the main views fit at 1366×768.

The graph uses one canonical source reading per completed step. Missing/stale readings break
lines; future hours stay blank. No night values, sunrise curve or missing samples are invented.
Leftover solar is displayed before battery charging/other constraints; it is not a new
forecast allocation or permission to run equipment.

`simulator.view` projects a few telemetry fields from saved publications. No schema migration,
new source query in the app, copied-history table, forecast change or LangGraph/agent change.
The delay persists in existing simulation JSON; old rows default to one second.
MCP stays read-only; PostgreSQL/pgvector, checkpoints, bounded calls, T3/T5/T6/T7 authority
and optional LangSmith are unchanged. Database risk is low: no data rewrite.

## Limits and rollback

A single selected wing runs at a time in one foreground process. The graph is sampled at
the chosen interval; it does not plot every raw scrape. Scrape time is capture time, not
independently verified inverter measurement time. Synthetic weather, retrospective voltage
floors and the existing forecast limits remain. The standalone source audit is an explicitly
authorized read-only diagnostic, separate from runtime MCP acquisition.

README, howto, runbook, architecture, observability, capstone notes and the audit document
are updated. Older submission files retain their original evaluation snapshots. Roll back
the UI/projection/scripts while preserving all simulation/publication history. Repo stays private.
