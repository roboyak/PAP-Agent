# PR01: local service and PostgreSQL foundation

**Lesson:** Prove the service and storage before adding intelligence.

## Scope and behavior

Small FastAPI package, read-only debug console, `/health`, `/api/v1/version`,
typed settings, PostgreSQL sessions, pgvector migration, locked dependencies,
Make targets, and local Playwright smoke tests.

UI built from scratch: the reference's Context, Memory, Tools, Subagent, and Trace tabs,
plus Health. Service checks show real request results and timing; future agent panels
start empty. No Gradio or frontend build tools.

Database failure or missing pgvector returns 503; version and the page remain available.
Application errors expose status without connection credentials.

## Architecture and runtime boundaries

- PostgreSQL is the system of record; pgvector lives in the same database.
- Hardware control, MCP, PAP calculations, LangGraph, LangChain, and LangSmith have no
  implementation in PR01. No external model, telemetry provider, or vector database is required.
- Graph state/nodes/edges, checkpoint/resume, interrupts, retries, and agent tool contracts:
  no changes. These start in their scheduled increments.
- Local logs: Uvicorn access logs. No telemetry, model traces, or private reasoning is recorded.
- UI/API show synthetic, read-only operation. PAP and DB services bind to loopback by default.

## Database / migration / configuration

`0001_enable_pgvector` enables the extension. No domain, embedding, or checkpoint tables yet.
Migration risk: **LOW**, additive. Downgrade preserves the extension and its potential dependents.
Sessions commit successful work and roll back exceptions. `DATABASE_URL` defaults to the
isolated native local database; `.env.example` documents it. Do not point it at the source DB.
